# SteelChallenge Phase 1

## Windows에서 실행

프로젝트 폴더에서 PowerShell을 열고 실행합니다. Python과 의존성이 이미 설치되어 있으면 마지막 명령만 실행하면 됩니다.

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

터미널에 표시되는 로컬 주소를 브라우저에서 엽니다. 함께 제공된 `steelchallenge.sqlite3`에 저장됩니다. 파일을 옮기거나 백업할 때 앱을 종료하세요. DB 파일이 없으면 최초 실행 시 스키마와 seed를 생성합니다. 별도 데이터베이스를 사용하려면 실행 전에 `STEEL_DB` 환경 변수에 파일 경로를 지정하세요.

## 첫 사용 순서

1. **품목·회수율**에서 품목 이름, 현재 UI 가격(통화/t), 원재료 벌크밀도(t/m³), 목표 원소 조성(wt%)과 출처를 입력합니다. 확인된 0은 0, 미확인 값은 빈칸이나 JSON의 `null`로 둡니다. 모든 비용에는 같은 통화를 사용합니다.
2. 단일 스크랩을 녹인 실제 Run에서 나온 용해 후 조성을 **단일 원재료 용해 실측**에 근거와 함께 기록합니다. 최적화는 해당 품목·원소 실측 평균을 사용하고, 값이 없는 원소에는 UI 조성과 경로의 EAF 잔존율을 사용합니다. 용해 조건이 서로 다르면 같은 평균에 섞기 전에 실측 근거를 검토하세요.
3. **강종 조건**에서 C·Mn 등 목표 원소의 Min/Max와 총시간(`time_min`), 최종 온도(`temp_c`), 슬래그 조건(예: `basicity`)을 입력합니다. 한쪽만 제한할 수 있습니다.
4. **공정 경로**에 실제 Run을 근거로 경로를 저장합니다. 예를 들어 CAS-OB와 RH를 따로 등록해 비용과 조건을 비교합니다. 같은 첨가물이라도 설비마다 회수율을 입력합니다.
5. **후보 탐색**에서 강종, 경로, 원재료 장입 kg과 Basket별 m³ 한도를 입력합니다. 결과에서 t당 총비용, 각 Basket의 원료 및 사용 부피, EAF/2차정련 첨가량, 예상 조건과 Event Log 초안을 확인합니다. 후보 JSON을 내려받아 실제 Run과 연결할 수 있습니다.
6. **Run 가져오기·비교**에서 원본 텍스트를 올리거나 붙여넣고 후보 JSON을 함께 저장합니다. 실제 최종 조성·공정·비용을 `{"chemistry":{"C":0.08},"process":{"time_min":42},"cost":{"per_t":123}}` 형태로 기록합니다. 이 예시 숫자는 형식 설명용입니다. 예측과 실측의 차이를 보고 입력 모델을 보정하고 다시 실행합니다. 시계열과 Run 기록을 Excel에서 열 수 있는 CSV로 내보낼 수 있습니다.

## 경로 입력 필드

| 필드 | 단위와 의미 |
| --- | --- |
| `facility`, `evidence` | 회수율과 같은 설비 이름, 실제 Run ID 또는 근거 |
| `eaf_min`, `move_min`, `secondary_min`, `mix_min` | EAF 경과, 이동, 2차정련 작업, 최종 첨가 후 혼합 대기 시간(분). 중복 없이 입력 |
| `tap_c`, `move_loss_c`, `secondary_delta_c` | EAF 출강 온도, 이동 중 온도 손실, 2차정련 순 온도 변화(°C, 감소는 음수) |
| `steel_yield` | 원재료 kg당 EAF 용강 kg (0 초과, 1 이하) |
| `retention` | 목표 원소별 EAF 잔존율(0~1) |
| `operations` | 전력, 산소, 가스, 시간, 이동 등 경로별 실제 총비용 |
| `slag` | 해당 경로로 예측한 슬래그 지표. 강종 조건과 같은 이름 및 단위 사용 |
| `eaf_kg` | EAF 고정 첨가량. 품목 슬롯별 kg 객체 |
| `secondary_max_kg` | 최적화에서 허용할 2차정련 첨가물별 kg 상한. 품목 슬롯을 키로 사용 |

회수율의 `bulk`는 투입 질량 중 용강에 남는 전체 비율입니다. 원소별 회수율은 첨가물에 들어 있는 해당 원소 질량 중 용강에 남는 비율입니다. EAF 첨가물의 설비 키는 `EAF`입니다. 용강에 잔류하지 않는 플럭스는 실측 근거가 있을 때 `bulk=0`과 해당 원소 기여 0을 입력할 수 있습니다.

## 계산과 데이터 범위

### Master 엑셀 Run 가져오기

이 배포본 DB에는 중복 제거 후 Master Run 84건과 PDF 신규 Run 49건이 있습니다. PDF 6건은 기존 Master Run에 출처를 연결했습니다. **Run 가져오기·비교**에서 실측과 Master 분석을 확인하고, 같은 조업을 재현한 후보 JSON을 연결해 예측 차이를 볼 수 있습니다. 기존 DB나 별도 DB에 가져오려면 프로젝트 폴더에서 다음을 실행합니다.

```powershell
python -m pip install openpyxl
python import_master.py "C:\Users\IT\Downloads\SteelChallenge_Master_20261103_170605.xlsx"
```

재실행 시 같은 Master Run ID는 건너뜁니다. 로그와 보고 결과가 일치하는 중복 Run은 한 건으로 연결합니다. 예측은 후보를 연결한 Run에서만 표시됩니다.

- 사용자가 제공한 현재 UI 엑셀의 원재료 10종과 EAF 첨가물 16종을 초기 DB에 반영했습니다. 원재료 벌크밀도, 표시 조성, 산화물 정보와 EAF dust의 음수 단가를 원본대로 보존합니다. 2차정련 첨가물 21개 슬롯은 해당 품목 데이터가 들어오면 채울 수 있습니다. 엑셀 빈칸은 미확인 값입니다.
- 기존 프로젝트를 업데이트하려면 실행을 종료하고 새 ZIP에서 `steelchallenge.sqlite3`를 제외한 파일들을 기존 폴더에 덮어쓴 뒤 다시 실행합니다. 기존 DB에 카탈로그가 한 번 반영됩니다. 같은 이름의 EAF 품목에 대해서는 엑셀에서 확인된 필드를 반영하고 기존 슬롯 ID를 유지합니다.
- 초기 조성 계산기는 UI 값의 장입 질량가중 평균을 계산합니다. Basket 부피는 kg ÷ (1,000 × 벌크밀도)의 합입니다. 합금 계산기는 원소별 회수 질량과 회수된 전체 질량을 합산해 동반 원소와 희석 효과를 계산합니다.
- 최적화는 연속 kg을 사용합니다. 등록 경로별로 목표 원소, 총 장입량, Basket 용량, 첨가물 상한을 제약으로 적용하고 완성 용강 t당 비용을 최소화합니다. 후보의 가능 여부는 입력 모델에 따릅니다. 실제 투입 단위, Basket 내 적층 순서, 경로별 실측 적용 범위는 시뮬레이터에서 검증해야 합니다.
- EAF 투입량, 슬래그 예측치, 시간, 온도 변화와 설비 경로는 등록한 경로에서 가져옵니다. Phase 1은 탈탄·슬래그 반응과 온도 이력을 독립적으로 시뮬레이션하거나 적층 순서를 최적화하지 않습니다. Event Log는 계획 초안이며 EAF 첨가의 조작 시각은 별도 결정이 필요합니다. 시뮬레이터가 읽는 실행 파일 형식은 실제 로그 원본으로 확인한 후 연동할 수 있습니다.
- 가져오기는 UTF-8 및 CP949 텍스트를 지원합니다. 줄 앞의 `HH:MM:SS` 또는 `MM:SS` 경과 시간과 `Sample C=0.08% Mn=0.70%` 형태의 표본을 인식합니다. 원문, 행 번호, 인식된 양과 미분류 이벤트를 보존합니다. 동일 원문은 한 번 저장됩니다. 실제 SteelChallenge 로그 원본이 없어 해당 로그 형식과 파서의 호환성은 미검증 상태입니다.
